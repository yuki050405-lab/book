# 読書録 — 私だけの書斎

React / TypeScript / Vite で作った、日本語の個人向け読書記録 Web アプリです。書斎をイメージした背景、木の本棚と背表紙、スマートフォン対応の画面を備えています。

## インストールせずに動作確認する

Windows に Node.js をインストールする必要はありません。開発環境側で `npm run build:portable` を実行すると、画像・スタイル・JavaScript を含む単一ファイル `releases/読書録.html` を生成できます。このファイルを Edge / Chrome で開く方式です。登録・感想・一節・本棚・バックアップをブラウザだけで扱えます。Google 連携は未設定です。書籍検索や OCR など外部通信を伴う機能にはネット接続とブラウザ側の許可が必要で、ファイル起点の通信は配信先の CORS 制約を受けます。

単一 HTML のテストはネット通信を遮断し、HTML 一つをテスト用 HTTP オリジンに渡して実行しています。テスト環境の管理ポリシーで `file://` への直接移動が拒否されるため、Windows 実機のファイル直接起動は未検証です。ブラウザがファイル内の保存を許可しない場合は、HTTPS で公開する版をご利用ください。バックアップ JSON は別途保存してください。

## GitHub Pages でブラウザ確認用に公開する

`npm run build:pages` は `/book/` 配下向けにビルドし、公開用ファイルを `docs/` に配置します。GitHub Pages の設定は **Deploy from a branch → main → /docs → Save** です。GitHub 側で公開が完了するまでは、想定される URL を動作済みのリンクとして扱わないでください。

公開用ファイルに読書データや認証情報は含みません。Google の設定がない間は閲覧者それぞれのブラウザ内に記録します。アプリの公開範囲は GitHub Pages の契約・設定に依存します。ご自身の読書記録が自動的に公開される仕組みではありません。

## 起動

Node.js 22 以降を使用します（開発時検証：Node.js 24）。

```sh
cd /workspace/book
npm ci --cache /tmp/npm-cache
npm run dev -- --port 5173
```

```sh
npm test             # ISBN、分類、重複、同期マージ等
npm run test:e2e     # Chromium のデスクトップ・iPhone サイズで操作確認
npm run build       # 型検査と配信用 dist の作成
```

E2E は `/usr/bin/chromium` を既定で使用します。別環境では `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` に Chromium の実行ファイルを指定してください。iPhone プロジェクトは Chromium による画面サイズ・タッチ操作のエミュレーションです。実機 Safari の代替にはなりません。

## 使える機能

- カメラの ISBN バーコード読み取り（ZXing）。ISBN チェックディジットを検証し、価格バーコードを除外。
- openBD → Google Books による ISBN 検索、書名・著者検索、ISBN がない電子書籍の手入力登録。
- 読みたい／読書中／読了、読了日、感想、しおり。再読は同じ記録を更新。
- 一冊に複数の一節。ページ・電子書籍の位置番号・章は任意。写真 OCR は日本語・英語対応、結果を確認・修正してから追加。
- 教育の12小分類、校種、複数タグ。分類は書名・紹介文などのキーワードからの推定で、手動変更可能。ISBN の番号そのものからは分類しません。
- 感想・一節を含む検索、テーマ別の棚、お気に入りの表紙展示、関連本のリンク。
- 授業で試したいこと、実践状況、振り返り。
- 今日の一節、昨年の同月の本、月別読了数・ジャンル別冊数。
- 登録成功・失敗通知、新規追加時の本棚アニメーション、動きを減らす設定への対応。
- 印刷ダイアログから読書ノートを PDF 保存、JSON バックアップの書き出し・追加読み込み。

## 保存と Google 連携

初期状態は**このブラウザの localStorage に保存するローカルモード**です。秘密のサーバーやダミー認証はありません。ブラウザのデータ消去、プライベートブラウズ終了、端末変更に備え、バックアップを保存してください。データは同一オリジンのスクリプトからアクセスできるため、共有端末での利用には注意してください。

Google を設定すると、アプリ専用の Google スプレッドシートを作成し「読書記録」「好きな一節」「授業で試したいこと」の3タブを更新します。編集時に重複行を増やさず、削除した一節も反映します。書き込みは明示的な文字列として扱うため、一節に `=...` を含んでも数式として実行しません。専用の3タブはアプリが上書きするため、手作業の追記には別タブをご利用ください。

端末間のアプリデータ共有には、自分の Drive に作成する `読書録-data.json` を使用します。同じ Google アカウント・同じ OAuth クライアントで接続してください。シートを読み戻す方式ではありません。記録ごとの更新日時が新しい側を採用し、複数端末で同じ本を同時編集した場合は後の更新が優先されます。共同編集や変更履歴の復元機能はありません。初回に二台から同時接続すると専用データが重複作成される可能性があるため、最初は一台から同期してください。同時に同じ本を編集する共同編集は対象外です。一台で同期完了を確認してから、もう一台で編集してください。

OAuth アクセストークンはメモリにだけ保持し、再読み込みや期限切れ後は再接続します。バックグラウンド同期失敗時も端末の記録は残ります。「今すぐ同期」で再試行できます。同期は接続中の画面が開いている間だけ実行します。保存後約1.2秒、約1分ごと、画面へ戻ったとき、通信復帰時に共有を確認します。画面上部に保存・共有状況を表示します。スプレッドシートが一時的に使えなくても、Driveへの共有は試み、転記待ちを表示します。端末の変更が同期中に発生した場合は新しい変更を保持し、次の同期を予約します。

### Google 初期設定（所有者が実施）

公開サイト用のクライアントIDは `.env.production` に設定済みです。これは公開可能な識別子で、クライアントシークレットではありません。公開版では各端末でのID入力は不要です。個人のメールアドレスや認証トークンはこのファイルに保存しません。

1. Google Cloud でプロジェクトを作成し、**Google Drive API と Google Sheets API** を有効にします。
2. OAuth 同意画面を設定し、テストユーザーはご自身の Google アカウントのみにします。
3. OAuth クライアントを「ウェブアプリケーション」として作成します。承認済み JavaScript 生成元に、開発時は `http://localhost:5173`、公開時は実際の HTTPS オリジンを登録します。
4. アプリの「他の端末と共有する」→「はじめての接続設定」にクライアントIDを入力し、「連携設定を保存」を押します。誤接続防止用のメールアドレスは任意で入力でき、このブラウザ内にだけ保存します。**パスワード・クライアントシークレット・アクセストークンは入力しません。**
5. 「Google でログイン」を押します。接続後、既存の端末内記録を消さずに共有データとまとめます。「Google と共有中」の表示を確認してください。
6. iPhoneや別ブラウザで同じ HTTPS アドレスを開き、同じクライアントIDを設定し、同じ Google アカウントで接続します。一度設定した値は各ブラウザに残ります。端末間同期は接続後に行われます。

接続のために Node.js をインストールしたり、ソースコードを変更したりする必要はありません。クライアントIDは公開可能な識別子です。管理者が `VITE_GOOGLE_CLIENT_ID` を指定してビルドすれば、各端末でのID入力も不要にできます。`VITE_ALLOWED_EMAIL` は旧来のビルド設定として引き続き読めますが、設定値が公開JavaScriptに入るため、個人のメールアドレスを非公開にしたい場合は空欄にし、ブラウザの設定欄を使用してください。

使用スコープは `drive.file` と `userinfo.email` です。アプリが作成・許可されたファイルだけにアクセスします。所有者の制限は Google OAuth のテストユーザー設定でも行ってください。静的サイト自体の公開範囲を制限する場合は、ホスティング側のアクセス制御も設定してください。

OAuth のテスト状態では再認証が必要になることがあります。実際のアカウント接続・シート作成・二端末同期は設定後に確認が必要です。

## カメラ・外部通信

iPhone Safari / パソコンカメラは HTTPS が必要です（localhost を除く）。ボタンを押した後、カメラ使用を許可してください。ダイアログを閉じる・登録方法を変えるとカメラを停止します。実機の読み取り精度は、照明・ピント・カメラに依存します。

- 書籍検索：`api.openbd.jp`, `www.googleapis.com`
- 表紙：書籍データの配信先（例 `cover.openbd.jp`, `books.google.com`, `books.google.co.jp`）
- Google：`accounts.google.com`, `www.googleapis.com`, `sheets.googleapis.com`
- OCR：`tessdata.projectnaptha.com`（日本語・英語学習データ）、`cdn.jsdelivr.net`（OCR ワーカー・WASM。認識は端末内）
- 書体：`fonts.googleapis.com`, `fonts.gstatic.com`（取得不可時は端末の書体へ切り替え）

背景画像 `public/study.webp` は、このアプリ用に生成した画像を同梱しています。ユーザー提供の参考写真そのものではありません。実際の背表紙画像ではなく、書名と著者による独自の背表紙を描画しています。

## 未検証・制約

- OAuth 初期設定と実アカウントが未提供のため、Google への実ログイン・シート作成・端末間同期は未検証です。
- クラウド環境の外部通信許可が反映されるまでは、書籍検索・OCR 用言語データ取得などがブロックされる場合があります。手入力と端末内保存は利用できます。
- 別ブラウザへの共有、感想の逆方向の反映、Sheets障害時のDrive共有はGoogle通信モックで検証しています。実アカウントでの検証を代替するものではありません。
- カメラ画面の起動・終了時の撮影停止は模擬カメラで検証しています。iPhone実機の読み取り精度や写真 OCR は実機で確認が必要です。ブラウザ自動テストの検索結果はモックで、実書籍 API の接続成功を示すものではありません。
- 退会・本自体の削除、オフライン専用 PWA、電子書籍ストアとの自動連携は現時点の対象外です。
